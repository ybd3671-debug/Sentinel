# 云端长期运行与验证

公开版本使用托管云任务每5分钟唤醒一次，调用受鉴权保护的 POST /api/tick。云任务不依赖浏览器开着，也不需要重新部署网页。部署实例导出 scheduled handler，供以后迁移到原生Worker Cron。

云任务运行指引：读取关联Site的最新get_site信息，从其返回值取得仅用于该Site的siwc_bypass_bearer_token。向同一Site的/api/tick发送POST，用Authorization Bearer传入该值；可同时用OAI-Sites-Authorization满足平台访问边界。不得把凭证写入源码、提示词、日志或报告。若缺失或鉴权失败，停止并报告，不能绕过鉴权。处理完毕读取/api/health确认schedulerLastTick更新。任务无需访问任何访客个人账户或连接器。

服务端SCHEDULER_TOKEN通过托管环境的secret配置，当前与Site服务凭证绑定。凭证发生变化时必须同步更新环境并重新部署；失败应显示为调度过期，不能伪装正常。

调度仅检查已到期且未暂停的任务。检查间隔允许1至1440分钟；云端唤醒计划为5分钟，云任务启动和网络可能造成额外延迟，因此不是实时行情告警系统，也不保证精确分钟级SLA。服务端记录最近实际调度时点，超过15分钟界面提示检查调度服务。

演示任务读取明确标注的构造快照。无需密钥即可完整检验监控状态机，但它不是实际市场数据。真实模式需要合法可用的行情接口凭据。

本地启动时每30秒检查到期任务；本地进程关闭后停止。API触发检查必须与访客的“手动检查”记录分开：manual=false表示调度执行。

发布后验收包括：认证失败返回401；受授权调用返回检查数量；关闭页面仍能执行；新建到期任务后调用调度产生manual=false记录；重新读取服务端状态和心跳；暂停任务不产生调度记录。
