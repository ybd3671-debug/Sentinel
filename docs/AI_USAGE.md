# AI使用与验证记录

## 使用范围

本作品使用 Codex 协助范围取舍、交互设计、规则引擎、服务端、界面、测试、文档和部署。应用运行时的模型接入为可配置能力；无密钥时使用明确标注的本地规则解析器，不能把开发时使用AI等同于运行时模型能力。

## 实际修正记录

1. 跌幅语义：自然语言“跌幅超过2%”转为 changePct < -2；通过负数阈值与触发快照测试确认，不将正数2当作下跌条件。
2. 数据失败不能生成未触发：对过期、缺失、冲突、未来时点、错误标的返回待核验，不把缺失值默认成0。
3. 日期时区：用上海自然日而非UTC日进行条件比较；测试UTC 18:00对应上海次日。
4. 去重语义：冷却结束不应对持续满足重复提醒，需解除后重新布防；测试验证这一完整状态链。
5. 路径兼容：本机首次启动时，包含中文的文件URL未正确转成本机路径，导致SQLite无法打开。改用标准 fileURLToPath 后服务成功启动。
6. 环境兼容：环境没有npm可执行入口，改用无依赖Node命令直接测试、启动和打包。

## 人工确认边界

产品要求用户确认规则后生效。模型输出格式、字段、运算符、数值范围都需代码验证；不执行模型生成代码。拒绝交易与收益承诺类需求，不能据此宣称具备全面语义合规检测。

以上由开发过程记录生成，候选人尚未逐项人工复核；未虚构候选人的修正或验收行为。提交前候选人需亲自体验并补充自己的判断和取舍。

7. 边界语义修正：超过采用严格比较，达到采用包含等号的比较，并新增阈值恰好相等的测试。
8. 公开访问前新增匿名工作区隔离、HttpOnly Cookie、事务写入和并发校验，避免访客之间混用任务或产生重复提醒。
9. 托管打包脚本在Windows使用了不兼容路径；保留标准构建产物，改用系统原生tar打包，部署成功。

## 本轮规则和数据复核

- 检查出混合且/或、相对日期和省略字段的区间条件可能造成误解：增加拒绝歧义、上海日期固定化、完整保留上下界和矛盾校验。以固定时间和构造快照验证，不借用真实行情推断正确性。
- 模型接口仍未配置；以模拟响应验证格式、超时和与明确规则不一致时拒绝生成，不能称为真实模型联调。
- 新增腾讯公开报价，实际访问五个固定标的，核对原文中的价格、涨跌幅和报价时点；自动测试使用构造响应，不把测试数值标为真实市场事实。
- 旧报价即使刚刚下载也必须待核验。待核验记录保留可追溯数值，同时将比较结果设为空，避免用户把陈旧数值当成有效判断。
- 独立GitHub环境已通过41项测试与构建；首次线上验收能访问D1，但后续任务操作返回404。修正验收客户端只保存一条Cookie的问题，完整线上结果以实际工作流记录为准，未通过前不宣称全链路通过。
